The first release whose binaries are **signed and notarized**. The analyzer itself does not change from v0.3.0; this release is about how `4d-components`, the opt-in standalone dependency manager, is built, signed and published, and about clearer documentation.

Documentation: https://miyako.github.io/4d-static-analysis/

## Signed releases

- **macOS:** the `4d-components` executables (arm64 and amd64) are signed with a Developer ID Application certificate with the hardened runtime and a secure timestamp, and **notarized by Apple**.
- **Every archive and `SHA256SUMS`:** signed with Sigstore (a `<file>.sigstore.json` bundle next to each file) and covered by a GitHub build-provenance attestation. Verify with `cosign verify-blob` or `gh attestation verify <archive> --repo miyako/4d-static-analysis`.
- **Releases are built by a workflow** (`Release`, manual, from `main`) that refuses to publish without the signing secrets. How it works and what is checked is in [`docs/releasing.md`](https://github.com/miyako/4d-static-analysis/blob/main/docs/releasing.md).

## Windows: Authenticode signing is pending

No Authenticode certificate is available yet. The Windows executables are therefore published as `4d-components-0.4.0-windows-<arch>-unsigned.zip`: they carry the Sigstore signature, the attestation and a checksum, but **no Authenticode signature**, so Windows SmartScreen may warn. Windows arm64 is cross-compiled and has not been run. As soon as a certificate is set up, the same workflow signs and verifies the Windows executables and the `-unsigned` suffix disappears.

## Clearer naming

In `dependency-manager: native` and `--dependency-manager native`, "native" means the **compiled standalone executable** `4d-components`, as opposed to the Python script. It is not a dependency manager built into tool4d (tool4d has none) and not 4D's own Dependency manager. The option value is unchanged. The README, the action input description, the CLI help and the behavior document now say so.

## Unchanged

- The default dependency manager is still the reviewed Python emulation; `4d-components` stays opt-in. Using it from the action is the same as in v0.3.0:

  ```yaml
  - uses: miyako/4d-static-analysis@v0.4.0
    with:
      download-tool4d: "true"
      project: Project/MyProject.4DProject
      dependency-manager: native   # default: python
  ```

- Analysis behavior, reports, the fail-closed contract and the GitHub token handling are unchanged.
- Still not covered: real tool4d runs with `4d-components` cover one fixture with one GitHub component; the Linux tool4d backend is unverified; the 4D 21 LTS GitLab policy of the analyzer (tool4d 21.0) is unchanged.
