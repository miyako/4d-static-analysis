The first release with the **native component manager**, `4d-components`, and a second, opt-in way to resolve 4D component dependencies. Nothing changes unless you ask for it: the default dependency manager is still the reviewed Python emulation.

Documentation: https://miyako.github.io/4d-static-analysis/

## Native component manager (opt-in)

- **`4d-components`:** an independent, standard-library-only Go executable that resolves, downloads, verifies, caches and installs the component dependencies of a 4D project. It needs no Python, no tool4d and no GitHub Actions. Commands: `resolve`, `install`, `inventory`, `verify`, `cache` (#22, #23).
- **Same behavior as the Python manager:** it follows the same observed 4D rules and writes the same report, 4D-compatible lock and archive-store formats. The Python reference and the native executable are compared on about 50 scenarios (version anchors, ranges, conflicting child declarations, cycles, local components, offline replay, tampered archives, outages, rate limits, rejected tokens, GitLab) on Linux, macOS and Windows. Every difference is listed in [`docs/component-manager-behavior.md`](https://github.com/miyako/4d-static-analysis/blob/main/docs/component-manager-behavior.md).
- **Safer than the reference where it matters:** archives are untrusted input (path, symlink, entry-type and size checks); a damaged cache folder, an unverifiable digest, a truncated release list or a token sent over `http` are failures, never a silent success; credentials are never accepted as arguments and never written to reports, locks or caches.
- **Fail-closed contract unchanged:** incomplete dependency resolution still makes the analysis incomplete (exit `2`).
- **Verified with a real runtime:** tool4d language-server analysis of the dependencies fixture with the native manager, online and offline, on macOS and Windows, with the same resolved tags as the Python manager. This covers one fixture with one GitHub component.

### Using it

```yaml
- uses: miyako/4d-static-analysis@v0.3.0
  with:
    download-tool4d: "true"
    project: Project/MyProject.4DProject
    dependency-manager: native   # default: python
```

The action builds `4d-components` from this release's own source. Locally: `sonar-4d … --dependency-manager native --dependency-manager-path <4d-components>`.

You can also run the attached executables directly. Checksums are in `SHA256SUMS`. **Windows arm64 is cross-compiled and has not been run.** These binaries are not signed.

## Not covered yet

- The native manager is not the default. GitLab components are covered by the mock-provider comparison only, and the analyzer still exposes only a GitHub token.
- Real tool4d runs with the native manager cover one fixture; the Linux tool4d backend is still unverified.
- The 4D 21 LTS GitLab policy for the analyzer (tool4d 21.0) is unchanged.

## Also

- Go 1.24 is required to build `4d-components` (older toolchains produce macOS binaries that abort at load).
- Version bump of the analyzer, package and Sonar plugin to 0.3.0.
